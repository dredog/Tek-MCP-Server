# Lessons Learned: Tek PTA Plugin Structure Requirements

**Date:** 2026-02-04 20:58  
**Test Name:** Tek PTA Plugin Structure Requirements

## Summary
Discovered that Tek PTA plugins silently fail to load when they don't follow the exact dataclass structure. Created new MCP tools (tek_pta_plugin_template and tek_pta_plugin_checklist) to ensure Claude always gets the correct structure before writing plugin code.

## Instruments Used
MSO4/5/6 Series Oscilloscopes, Tek PTA Framework

## Key SCPI Commands
MEASUrement:MEAS:TYPe, MEASUrement:MEAS:SOUrce1, MEASUrement:MEAS:SOUrce2, MEASUrement:DELETEALL, MEASUrement:MEAS:STATistics:ENABle

## Gotchas / Problems Encountered
1. Plugins with incorrect TestSuitePlugin field order SILENTLY FAIL - no error message shown
2. engine_class MUST be the last field in TestSuitePlugin dataclass
3. TestEngineBase.__init__ MUST take instrument_manager parameter
4. register_suites() function is REQUIRED - plugins won't load without it
5. TestPoint field order and types must match exactly
6. Claude's search finds fragments but doesn't guide to read the full Plugin Guide first

## Solutions
1. Created tek_pta_plugin_template() MCP tool that returns the EXACT correct template
2. Created tek_pta_plugin_checklist() MCP tool with development checklist
3. Added memory instruction: "ALWAYS call tek_pta_plugin_template() FIRST"
4. Updated search to warn when plugin queries detected
5. Always copy dataclass definitions from working plugins, never write from scratch

## Measurement Tips
For reference waveforms (REF1, REF2): Skip ALL acquisition commands - no trigger, no ACQ:STATE RUN. Reference waveforms are static pre-captured data.

## Additional Notes
The TEK_PTA_PLUGIN_GUIDE.md already has all the correct information in Section 2 (Quick Start Template) and Section 3 (CRITICAL Plugin Structure Requirements). The problem was that Claude wasn't being directed to read it first. The new MCP tools surface this information prominently.
