# Lessons Learned: MSO58LP Overtemperature / Thermal Status Investigation

**Date:** 2026-03-17 16:13  
**Test Name:** MSO58LP Overtemperature / Thermal Status Investigation

## Summary
Investigated whether the MSO58LP exposes any SCPI-accessible path to query overtemperature or thermal health status. Exhaustive search across temperature, overheating, thermal, warning, STATus:QUEStionable, STATus:OPERation, diagnostic, and system alarm commands found nothing in the MSO SCPI database. Live confirmation via instrument query.

## Instruments Used
MSO58LP oscilloscope

## Key SCPI Commands
STATus:QUEStionable:CONDition? — NOT IMPLEMENTED (query timed out on MSO58LP)
STATus:OPERation:CONDition? — NOT in MSO SCPI database
DIAGnostic:RESult:TEMPerature? — AWG only, not present on MSO series
STATus:QUEStionable:MAP — NOT in MSO SCPI database

## Gotchas / Problems Encountered
1. STATus:QUEStionable:CONDition? timed out on live MSO58LP — not implemented, instrument held the bus with no response.
2. The MCP server MSO SCPI database contains no temperature, thermal, overheating, or warning-related commands for the MSO family.
3. STATus:QUEStionable hierarchy (including bit 4 = Temperature) comes from SCPI-99, NOT IEEE 488.2. Tektronix MSO scopes comply with IEEE 488.2 common commands but do not fully implement the SCPI-99 STATus:QUEStionable subsystem.
4. Vector store returned SYSTem:ALARm:COUNt:OTEMperature? and SOURstat:Overtemp? as suggestions — these are Keithley SMU/TSP commands that bled into the vector store from wrong instrument docs. Do not use.
5. AWG5200 and AWG70000 DO implement STATus:QUEStionable:CONDition? and DIAGnostic:RESult:TEMPerature? — these are AWG-only, not portable to MSO.

## Solutions
No SCPI solution exists. The MSO58LP handles thermal conditions entirely in firmware — fan control, throttling, and shutdown — with no programmatic visibility via SCPI. The instrument displays an on-screen thermal warning but does not surface this state to the bus. If thermal monitoring is required in a production test sequence, it must be handled at the system level (e.g., external temperature sensor, chassis monitoring) rather than via instrument SCPI.

## Measurement Tips
If overtemp detection is critical for a test application, consider: (1) polling ALLEV? after suspected thermal events to see if any error codes appear in the queue, though this is undocumented behavior; (2) external thermal monitoring at the rack/chassis level independent of the instrument SCPI interface.

## Additional Notes
This investigation also clarified an important distinction: IEEE 488.2 defines the bus standard and common commands (*CLS, *ESE, *ESR?, *IDN?, *OPC, *RST, *SRE, *STB?, *TST?, *WAI) and the Status Byte / Standard Event Status Register structure. STATus:QUEStionable is a SCPI-99 construct layered on top — it is optional and the MSO series does not implement it.
