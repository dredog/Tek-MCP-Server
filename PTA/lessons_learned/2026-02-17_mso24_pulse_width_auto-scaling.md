# Lessons Learned: MSO24 Pulse Width Auto-Scaling

**Date:** 2026-02-17 14:31  
**Test Name:** MSO24 Pulse Width Auto-Scaling

## Summary
Auto-scaling routine for MSO24 that uses Autoset as a starting point, checks for clipping via CH<x>:CLIPPING?, widens clipped channels, then sets exact V/div for 80% fill.

## Instruments Used
MSO24 oscilloscope

## Key SCPI Commands
CH<x>:CLIPPING? — returns 1 if channel is clipping, 0 if not. NOT in the SCPI JSON database but works on MSO2 series. MEASUrement:ADDMEAS PK2PK/HIGH/LOW/FREQUENCY for signal characterization. MEASUrement:LIST? returns MEAS1,MEAS2,... format (need to strip MEAS prefix). CH<x>:SCAle accepts arbitrary values (not restricted to 1-2-5 steps). MEASUrement:IMMed does NOT exist on MSO2/4/5/6 series.

## Gotchas / Problems Encountered
1. Autoset can clip signals — must check CH<x>:CLIPPING? before trusting HIGH/LOW measurements. 2. MEASUrement:LIST? returns 'MEAS1,MEAS2,...' not just numbers — need to strip MEAS prefix. 3. MEASUrement:IMMed is a legacy command that does NOT exist on MSO2/4/5/6 series. 4. Vertical scale accepts any value (e.g. 300mV, 600mV) — no need to round to 1-2-5 steps. Scope may snap to nearest valid step internally. 5. For 80% fill target, scale = pk2pk / 8 (10 divs × 0.80). Fill between 50-90% is acceptable; over 90% hides clipping, under 50% wastes screen space.

## Solutions
1. Use Autoset first (good horizontal starting point), then check CLIPPING? on each channel. If clipping, widen to 5V/div + 0V offset and re-acquire before characterizing. 2. Parse MEAS prefix: token.strip().upper().replace('MEAS', ''). 3. Use ADDMEAS + MEAS<x>:RESUlts instead of IMMed. 4. Send exact calculated scale value to CH<x>:SCAle and read back with CH<x>:SCAle? to see what scope actually set.

## Measurement Tips
For auto-scaling: characterize with PK2PK, HIGH, LOW, FREQUENCY. Set scale = pk2pk/(10*0.80) for 80% fill. Set offset = (HIGH+LOW)/2 to center signal. Set horizontal = 3 cycles / 10 divs using slowest frequency in the group.
